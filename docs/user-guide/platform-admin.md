# لوحة إدارة المنصة

افتح `/admin` أو `/platform`. الحساب منفصل عن مستخدم المؤسسة، وكل طلب API يتحقق من جلسة المشرف وصلاحياته. لا يوجد اسم مستخدم أو كلمة مرور افتراضيان.

## تفعيل المالك لأول مرة

بعد تشغيل PostgreSQL وتطبيق migrations وبناء الحزم:

```powershell
pnpm platform:bootstrap
```

أدخل البريد والاسم وكلمة مرور من 12–128 حرفاً في الطرفية. حقل كلمة المرور مخفي ولا تُمرر الكلمة كمعامل shell أو تُكتب إلى ملف. الأمر يستخدم MIGRATION_DATABASE_URL لإنشاء المالك الأول والإعدادات فقط، ويرفض استبدال مالك قائم. اختر بياناتك الحقيقية بنفسك؛ حسابات الاختبار مؤقتة ولا تصلح للدخول إلى قاعدة التطبيق.

## الأقسام المتاحة

- نظرة عامة: أعداد فعلية من قاعدة البيانات وصافي القيود اليدوية بوحدة OMR.
- المؤسسات: بحث وقائمة بيانات تعريفية وإيقاف/استعادة الوصول. لا يعرض محتوى المهام أو ملفات العملاء.
- المستخدمون: أسماء وبريد وحالة الوصول؛ تعديل الاسم وإيقاف الحساب مع إبطال جلساته.
- حسابات المشرفين: إنشاء حسابات بكلمات مرور hashed وأدوار، وتعديلها أو تعطيلها وإبطال جلساتها. عمليات الإدارة هذه للمالك فقط، وحساب المالك محمي من التعطيل وإعادة تعيين الدور هنا.
- الأدوار والصلاحيات: أدوار مخصصة وصلاحيات عرض/إدارة لكل قسم. تغييرات الصلاحيات تُفحص مجدداً على كل طلب؛ الواجهة ليست الحماية الوحيدة.
- الباقات: سعر شهري للمقعد وmax seats وstorage MB وAI credits وتفعيل/تعطيل. سعر الاشتراك يحتفظ بنسخة وقت إنشائه ولا يتغير بتعديل سعر الباقة.
- الاشتراكات: ربط مؤسسة بباقة وعدد مقاعد وتاريخ نهاية وحالة. يرفض الخادم تجاوز حد مقاعد الباقة، ولا يسمح بأكثر من اشتراك قائم للمؤسسة.
- الفواتير: إنشاء رقم فريد ومبلغ واستحقاق. يسمح بإلغاء فاتورة دون قيود مرتبطة فقط.
- القيود والمعاملات: تسجيل يدوي لوارد أو صادر مع مرجع فريد ومبلغ دقيق حتى 3 منازل عشرية؛ القيد غير قابل للتعديل والحذف. يصحح الخطأ بقيد مقابل. ربط القيد بفاتورة يحدث حالة تسديدها يدوياً.
- الصفحات: مسودة/منشور/مؤرشف، ورابط ومحتوى نصي. المسودات لا تُعرض للعامة، والنص لا ينفذ HTML أو JavaScript.
- إعدادات الموقع: الاسم وبريد الدعم والتذييل وصيانة الصفحات العامة وتفعيلها وسياسة مدة الجلسة.
- الأمن والجلسات: إبطال جلسات المشرفين وتغيير كلمة المرور وإبطال جميع جلسات الحساب عند تغييرها.
- سجل التدقيق: سجل append-only للدخول والتغييرات الحساسة، مع الفاعل والطلب والمورد، ودون كلمات المرور أو رموز الجلسات.
- المراقبة: حالات PostgreSQL وRedis وBullMQ وS3، وذاكرة العملية ومدة تشغيلها. الفشل يظهر كفشل فعلي؛ لا تُعرض نجاحات تجريبية.

القوائم تدعم البحث والصفحات. النماذج تحفظ في PostgreSQL وتعرض أخطاء الصلاحيات والتحقق والتكرار. يوجد دعم العربية/RTL والإنجليزية/LTR والهاتف.

## حدود التنفيذ

القيود المالية ليست خصماً أو تحويلاً مصرفياً، وبوابة الدفع غير مفعلة. لا يوجد تجديد أو تحصيل اشتراك آلي بعد. حدود التخزين وAI إعدادات محفوظة تحتاج ربطاً بوحدات الاستهلاك عند تنفيذها. MFA واستعادة كلمة المرور بالبريد والتنبيهات الأمنية الخارجية وSIEM لم تنفذ. خدمات المهام والملفات وتسجيل المؤسسة العام لا تزال ضمن المراحل اللاحقة؛ اللوحة لا تدعي تشغيلها.

## PostgreSQL محلي على Windows دون Docker

```powershell
pnpm db:local
pnpm db:migrate
pnpm build
pnpm platform:bootstrap
pnpm dev
```

البديل يستخدم PostgreSQL حقيقياً من الحزمة الاختيارية Windows x64، في `.local/postgres`، على 127.0.0.1:55432 وبمصادقة SCRAM. لا يعدل خدمات PostgreSQL/Redis الأخرى. `pnpm db:local:stop` يوقف عنقود المشروع ويحفظ البيانات. Docker Compose يبقى المسار الآخر؛ لا تشغله بالتوازي على منفذ PostgreSQL نفسه.

البديل محلي للتطوير فقط؛ لا يعالج تعطل Docker أو يشغّل Redis/S3. استمرار توقفهما يظهر في المراقبة، بينما وظائف الإدارة المبنية على PostgreSQL تبقى قابلة للاستخدام.
