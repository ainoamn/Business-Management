# النسخ والاستعادة

Volumes محلية مستمرة، و`pnpm infra:down` لا يحذفها. لا تستخدم `docker compose down -v` على بيانات تحتاجها. نسخة PostgreSQL ينبغي أن تُشفّر وتُنقل خارج الجهاز بصلاحيات منفصلة وسياسة احتفاظ معتمدة.

خطوات التشغيل: pg_dump بصيغة custom بواسطة حساب نسخ يقرأ البيانات المصرح بها؛ التحقق من exit code وحجم الملف وchecksum؛ تسجيل وقت النسخة؛ اختبار pg_restore في قاعدة منفصلة؛ تطبيق منح work_app وRLS والتحقق منها؛ ثم مقارنة أعداد السجلات ومهاجرات Prisma.

لا تستخدم إعادة توجيه binary في Windows PowerShell القديم؛ استخدم pg_dump -f داخل الحاوية ثم docker cp. credentials تمر عبر بيئة الحاوية، ولا تنشرها في الأوامر أو التقارير.

يحتاج تخزين S3 إلى نسخة منفصلة متسقة مع metadata، وRedis إلى تحديد ما هو قابل لإعادة البناء وما هو طابور دائم. حدد RPO/RTO مع مالك المنتج وقس زمن الاستعادة فعلياً. نُفذ التمرين المعزول الموثق أدناه، ولا توجد أرقام RPO/RTO إنتاجية مضمونة.

## تمرين الاستعادة المعزول — 2026-11-04

أصبح `pnpm test:restore` ينفذ نسخة custom فعلية باستخدام pg_dump ثم pg_restore إلى قاعدة مؤقتة مستقلة، بدل طباعة أوامر فقط. ينشئ قاعدتي مصدر وهدف بأسماء عشوائية محصورة في restore_source وrestore_target، ويطبق المهاجرات ويزرع بيانات اختبار فقط. لا ينسخ قاعدة المستخدم ولا يستبدل بياناتها.

نجح تمرين في 2026-11-04 باستخدام PostgreSQL 18.6: 116 جدولًا و79 سجلًا في لقطة الاختبار، مع SHA-256 للأرشيف ومقارنة أعداد السجلات وبصمات محتويات جميع الجداول، ومنح الجداول وFORCE RLS والسياسات، وهويات القيود وأعمدتها وحالة صلاحيتها وتعريفات القيود غير CHECK. يختبر رفض ساعات سالبة وربط مهمة بمشروع مؤسسة أخرى، ويعيد فك سر MFA بالمفتاح المستقل في الذاكرة، ويختبر العزل بحساب work_app على القاعدة المستعادة. لا تُقارن الكتابة النصية لتعابير CHECK حرفيًا لأن PostgreSQL يعيد تنظيم بعض الأقواس وتحويلات المصفوفات أثناء إعادة التحليل.

يحفظ manifest وأرشيف بيانات الاختبار في `.local/restore-drills`. ينظف قاعدتي الاختبار فقط حتى عند الفشل. عدد الجداول يتغير بإضافة المهاجرات؛ لا يمثل زمن الاختبار الصغير ضمان RTO على بيانات الإنتاج. حساب النسخ والمفاتيح وتخزين المستندات ونسخة خارج الجهاز وسياسة الاحتفاظ تحتاج إعدادًا تشغيليًا مستقلًا.

يلزم pg_dump وpg_restore الموافقان للإصدار الرئيسي للخادم. يقرأ المشغل PG_BIN_DIR، أو أدوات PostgreSQL المحلية في `.local/postgresql-tools-18.6` على Windows، أو PATH على الأنظمة الأخرى. الأدوات المحلية مأخوذة من [صفحة EDB المرتبطة بتنزيل PostgreSQL الرسمي](https://www.enterprisedb.com/download-postgresql-binaries). لا يُشغَّل installer ولا يُعدل خادم PostgreSQL أو خدمات الجهاز.
