# الدعم الفني

المستخدم `/app/support`، وفريق الدعم `/platform/support`. يستطيع العضو النشط ذو البريد المؤكد إنشاء بلاغ ومتابعته. يرى العضو بلاغاته فقط، ويرى مالك المؤسسة ومشرفها بلاغات المؤسسة. يمكن للمستخدم اختيار التصنيف والأولوية وإرسال تفاصيل نصية، مع إيضاح أن فريق الدعم ومشرفي المؤسسة يستطيعون قراءتها وضرورة عدم إرسال كلمات مرور أو مفاتيح.

تحتاج لوحة الدعم المنفصلة support.read للقراءة وsupport.manage للرد وتغيير الحالة. تفحص سياسة PostgreSQL الحساب والدور والجلسة الحالية؛ يسجل الوصول إلى قائمة البلاغات وفتح البلاغ والرد وتغيير الحالة. لا تتيح هذه الصلاحية الاطلاع على ملفات المؤسسة أو المحادثات أو المهام الخاصة. البيانات المتاحة للدعم هي البيانات التي أرسلها المستخدم لهذه القناة، مع أسماء الجهات والأعضاء المرتبطة بالبلاغ.

الحالات OPEN وIN_PROGRESS وWAITING_CUSTOMER وRESOLVED وCLOSED. رد فريق الدعم ينقل إلى انتظار المستخدم، ورد المستخدم يعيد الحالة إلى مفتوح. يحتاج البلاغ المغلق إعادة فتح صريحة قبل الرد. تُرفض النسخ القديمة، وتمنع مفاتيح الطلب المكررة إنشاء بلاغ أو رسالة مكررة حتى تحت التزامن. الرسائل append-only. حد إنشاء البلاغات خمس خلال ساعة للعضو؛ لا يمنع الحد متابعة بلاغ موجود. عدد الرسائل محدود أيضًا لمقاومة الإساءة، وتُرقّم الصفحات.

السياسات FORCE RLS، والمفاتيح الأجنبية المركبة للمؤسسة والعضوية والبلاغ تمنع خلط بيانات المؤسسات. هوية البلاغ ثابتة، ويجب أن تتقدم نسخته عند التحديث. كل رسالة لها مؤلف واحد فقط: عضو المؤسسة أو حساب الدعم. رد الدعم ينشئ إشعارًا خاصًا بصاحب البلاغ، مع مراعاة تعطيل إشعارات التطبيق، ودون نسخ نص الرسالة إلى قنوات أخرى.

ليس هناك وصول دعم استثنائي تلقائي إلى مستند أو مشروع بمجرد إرفاق معرفه في نص البلاغ؛ يظل النص نصًا ولا تُنفذ منه أوامر أو HTML. لم يُفعل إرسال خارجي جديد عبر البريد أو WhatsApp لهذه الوحدة؛ تبقى الردود داخل التطبيق.
