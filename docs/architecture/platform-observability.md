# التخزين وسجلات أخطاء المنصة

`/platform/storage` يعرض بايتات التخزين والرفع المحجوزة وعدد المستندات وإصداراتها لكل مؤسسة، مع البحث والترقيم. يعتمد على العدادات والسجلات الفعلية، ولا يُظهر عناوين المستندات أو مفاتيح التخزين أو المحتوى. يحتاج storage.read. دالة SECURITY DEFINER محدودة الأعمدة تتجاوز RLS لهذا التجميع المصرح فقط، مع فحص الحساب والدور والجلسة الحالية داخل قاعدة البيانات.

`/platform/errors` يحتاج monitoring.read، ويعرض أحداث أخطاء الخادم بأرقام الطلبات وتصنيف محدود وطريقة HTTP ونمط المسار والتاريخ. لا يخزن نص الخطأ أو stack أو body أو query أو headers أو كلمات المرور. يسجل ErrorFilter الحدث دون إبطاء استجابة الخطأ، بحد عشرين كتابة معلقة. إذا تعذرت قاعدة البيانات يبقى سجل stderr المهيكل برقم الطلب، ولا يعد تخزين قاعدة البيانات سجلًا مضمونًا لكل انقطاع. التسجيل يبدأ من تفعيل هذه المهاجرة؛ لا تُختلق أخطاء قديمة.

الجدول append-only لحساب التطبيق: INSERT وSELECT بحسب تفويض المشرف، مع منع UPDATE وDELETE وTRUNCATE. قراءة السجلات تفحص صلاحيات المشرف والجلسة داخل المعاملة؛ مجرد معرفة رقم طلب لا يتيح الوصول إليه. القيم المرسلة للواجهة لا تتضمن محتوى العميل.

المراقبة تفرق بين عدم إعداد المزود، وتهيئته دون إثبات اتصال، وصندوق البريد المحلي للتطوير. وجود الإعدادات ليس إثبات دفع حي أو إرسال بريد أو نجاح اتصال بمزود AI.

المسارات الموثقة `/platform/dashboard` و`/platform/audit-logs` و`/platform/payments` و`/platform/ai-usage` تفتح نظرة عامة وسجل التدقيق والقيود المالية وتبويب استخدام AI على التوالي، مع صلاحيات الوحدات نفسها.
