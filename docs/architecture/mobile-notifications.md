# تهيئة تنبيهات SMS وWhatsApp

أُعد الربط باستخدام Twilio كمحوّل مرجعي خلف `MobileNotificationProvider`، مع تحقق الهاتف وطابور PostgreSQL. يمكن إضافة محوّل آخر خلف الواجهة نفسها. لا يوجد حساب مزوّد في هذه البيئة، ولا تُرسل رسائل خارجية دون الإعدادات الحقيقية. `SMS_PROVIDER_URL` و`WHATSAPP_PROVIDER_URL` القديمان لا يفعّلان إرسالًا عامًا إلى عناوين مخصصة.

## إعداد الحساب لاحقًا

1. شغّل `pnpm messaging:setup`. يولد مفتاح تشفير عشوائيًا إلى `.local/mobile-configuration.env`، دون طباعته أو تفعيل الإرسال أو استبدال ملف موجود. انسخ قيمته إلى بيئة الخادم الخاصة، واحتفظ بنسخة آمنة مستقلة منه.
2. أضف `TWILIO_ACCOUNT_SID` ومعه مفتاح API محدود الصلاحيات `TWILIO_API_KEY_SID` و`TWILIO_API_KEY_SECRET`. يدعم الربط أيضًا `TWILIO_AUTH_TOKEN` للاختبار الحسابي. لا تضع الأسرار في الكود أو المحادثات أو Git.
3. أنشئ Verify Service وأضف `TWILIO_VERIFY_SERVICE_SID`. تُنشأ الرموز لدى المزوّد، وتُراجع عبر معرف التحقق نفسه. استخدم ضوابط Fraud Guard والمناطق المسموحة في حساب المزوّد. [توثيق إنشاء التحقق](https://www.twilio.com/docs/verify/api/verification)، [توثيق فحص الرمز](https://www.twilio.com/docs/verify/api/verification-check).
4. لـSMS: أضف مرسلًا دوليًا في `TWILIO_SMS_FROM` أو Messaging Service في `TWILIO_MESSAGING_SERVICE_SID` مع مرسل SMS مناسب.
5. لـWhatsApp: أضف `TWILIO_WHATSAPP_FROM` بصيغة دولية دون `whatsapp:`، و`TWILIO_MESSAGING_SERVICE_SID`، وقالبًا معتمدًا في `TWILIO_WHATSAPP_CONTENT_SID`. يتوقع المحوّل متغيرًا واحدًا باسم `1` يحمل رابط صندوق إشعارات المنصة؛ يجب أن يطابق القالب المعتمد هذا العقد. لا يُرسل نص مهمة أو اسم عميل. [توثيق القوالب وحقول الإرسال](https://www.twilio.com/docs/content/send-templates-created-with-the-content-template-builder).
6. اضبط `WEB_ORIGIN` على عنوان عام عبر HTTPS وأعد تشغيل API. يعرض النظام جاهزية التحقق وكل قناة بصورة مستقلة. تهيئة المفاتيح لا تثبت قبول المرسل أو القالب أو قابلية التسليم؛ اختبر رقمًا مسموحًا وقالبًا حقيقيًا في حسابك قبل الإطلاق.

## التفعيل الشخصي

في `/app/notifications` يظهر قسم تنبيهات SMS وWhatsApp. يدخل الشخص رقمًا يملكه ويوافق على رمز التحقق، ثم يدخل الرمز. التحقق لا يفعّل تنبيهات دورية تلقائيًا؛ يختار الشخص موافقة SMS وWhatsApp بصورة مستقلة ويحفظها. لا يؤخذ رقم ملف الموظف كرقم تنبيه موثّق.

الرقم مرتبط بعضوية المؤسسة، ويخزن مشفّرًا مع بصمة محمية بالمفتاح. لا تعيد الواجهات الرقم الكامل أو أسرار الإرسال، بل نهايته وحالة التحقق. تحدد مهلة التحقق بعشر دقائق وخمس محاولات، ولا تستطيع جلسة أخرى استخدام التحدي. صلاحية ملكية الرقم 90 يومًا؛ استبداله يعيد طلب الموافقات ويلغي المنتظر للرقم القديم. إلغاء الرقم يمحو قدرة الإرسال ويوقف المنتظر.

تستمر الموافقات بعد تسجيل الخروج العادي. تغيير كلمة المرور أو إعدادات MFA أو تعطيل الحساب يلغي تنبيهات الهاتف ويتطلب التحقق والموافقة مجددًا. تعطيل العضوية أو المؤسسة وإلغاء الوصول إلى السجل يمنع إرسال العمل المنتظر؛ لا يمكن سحب طلب سبق أن وصل إلى المزوّد.

## حدود الإرسال والنتائج

القيم الافتراضية: `NOTIFICATION_DAILY_VERIFICATION_LIMIT=100` لطلبات التحقق في الخدمة خلال 24 ساعة، و`NOTIFICATION_DAILY_USER_LIMIT=20` لطلبات التنبيه للحساب عبر كل مؤسساته، و`NOTIFICATION_DAILY_GLOBAL_LIMIT=200` للخدمة. تضاف حدود المستخدم والرقم وIP ومهلة 60 ثانية لإعادة طلب الرمز. هذه حدود عددية للمحاولات وليست ميزانية مالية مضمونة، وقد تترتب تكاليف لدى المزوّد.

يثبت طلب التنبيه في المعاملة التي تنشئ الحدث نفسه. يتحقق العامل من العضوية والصلاحيات والرقم والموافقة مرة أخرى، ثم يرسل خارج المعاملة. الطلب محدود المهلة والحجم، إلى نطاقات Twilio الثابتة دون متابعة التحويلات، ولا تسجّل أجسام رد المزوّد أو أرقام الهواتف أو الرموز.

يعاد فقط رفض 429 المؤكد أنه لم يعالج، مع تأخير وحد للمحاولات. [يوضح Twilio أن طلبات 429 غير معالجة ويمكن إعادة محاولتها](https://www.twilio.com/docs/api/errors/20429). نتيجة الشبكة غير المؤكدة أو انتهاء حجز عامل بدأ الطلب تُحفظ `UNCERTAIN` دون إعادة تلقائية، لتجنب تكرار طلب قد يكون مدفوعًا. فشل إعداد المرسل أو بيانات الدخول يتطلب مراجعة. لا تعني `ACCEPTED` إلا قبول المزوّد للطلب؛ لا تثبت وصول الهاتف أو القراءة. يعرض السجل هذه الفروق ولا يدعي وجود إيصالات تسليم حية.

## واجهات النظام والتحقق

الواجهات تحت `/api/v1/work/organizations/:organizationId/notification-phone`: قراءة الحالة، و`POST start` بجسم `{phone,consent:true}`، و`POST check` بجسم `{challengeId,code}`، و`POST consent` بجسم `{version,sms,whatsapp}`، وإلغاء الرقم بـ`DELETE`، وسجل الطلبات عبر `GET deliveries`. كل الكتابات محمية بالجلسة وCSRF، والسجلات خاصة بالعضو.

نجحت ستة اختبارات لعقد المحوّل و17 حالة API للهاتف على قاعدة مستقلة مع مزوّد اختباري. تشمل التشفير والجلسات والموافقات والطابور والتراجع والحدود وإلغاء الوصول والطلبات غير المؤكدة وتغيير بيانات الدخول. لا تمثل هذه الاختبارات إرسالًا حيًا أو اعتماد حساب أو قالب لدى Twilio.
