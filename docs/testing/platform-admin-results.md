# تحقق لوحة الإدارة — 2026-11-03

## ما تحقق فعلياً

- تشغيل PostgreSQL محلي حقيقي على Windows دون تعديل Docker أو أي خدمة قائمة.
- تطبيق migrations للأساس والإدارة في قاعدة التطبيق، وتطبيقها من جديد على قواعد اختبارات معزولة.
- Lint وType Check للحزم والتطبيقات والاختبارات، وبناء Next.js وNestJS.
- 24 اختبار وحدة، منها hashing والتحقق من كلمات المرور وCSRF وOrigin والصلاحيات والمال والحدود ومخططات الإدخال.
- 16 اختبار API تكامل ناجحة، مع إنشاء وحذف قاعدة اختبار مستقلة، بما فيها تغيير كلمة المرور وإبطال الجلسات السابقة.
- 8 فحوص عزل مؤسسات ناجحة على PostgreSQL الفعلي (`pnpm test:tenant`)، مع استثناء 4 فحوص بنية تحتية من هذا الأمر صراحة.
- 6 فحوص واجهة التأسيس على desktop/mobile، باستخدام network fixtures معلنة داخل الاختبار فقط؛ اجتازت بعد إضافة رابط الإدارة.
- 11 نقطة تحقق في رحلة متصفح حقيقية ناجحة دون mock للـAPI: دخول المالك، حفظ باقة وإعادة تحميلها، إنشاء اشتراك وفاتورة وقيد OMR بقيمة 0.010، نشر نص آمن، إنشاء دور، إنشاء مشرف محدود ورفض وصوله وتعطيل جلسته، حفظ إعدادات الموقع، حالات مراقبة فعلية، RTL/LTR وهاتف، وخروج دون أخطاء JavaScript.
- `pnpm audit --audit-level moderate`: لا ثغرات معروفة في النسخ المقفلة وقت الفحص.

## عطل جرى إصلاحه

مرّت assertions التكامل الأولى، لكن إغلاق عامل BullMQ عند غياب Redis علق حتى مهلة afterAll. عُدل العامل إلى تهيئة عند أول probe بعد تحقق اتصال Redis. أعيد التشغيل ومرّت المجموعة كاملة مع التنظيف. لا يعتبر التشغيل الأول الفاشل نجاحاً كلياً.

## البيانات واللقطات

اختبارات الإدارة تنشئ قواعد بأسماء عشوائية `platform_test_*` و`platform_ui_*` على المضيف المحلي فقط، وتزيل القاعدة التي أنشأتها عند الانتهاء. لا تعيد ضبط قاعدة التطبيق ولا تنشئ حسابات افتراضية فيها. اللقطتان `admin-desktop.png` و`admin-mobile.png` من بيانات اختبار معزولة موسومة في الواجهة، وليستا بيانات عملاء.

## ما لا تثبته هذه النتائج

لا تثبت جاهزية تجارية أو امتثالاً أمنياً شاملاً أو تحصيلاً عبر بوابة دفع. Redis/S3 وDocker ما تزال تحتاج بيئة تشغيل سليمة، وMFA والبريد والمراقبة الأمنية الخارجية غير منفذة. اختبارات Foundation E2E التي تشترط جميع الخدمات ready ليست مقبولة كناجحة لمجرد نجاح لوحة الإدارة.
