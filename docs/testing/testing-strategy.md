# استراتيجية الاختبار

- Unit: shared schemas وبيئة التشغيل ومفاتيح الترجمة؛ لا تحتاج خدمات.
- Integration: تطبيق NestJS المترجم وPostgreSQL/Redis/BullMQ/S3 حقيقية؛ بيانات اختبار عشوائية يتم تنظيفها بالمعرفات فقط. لا mocks لهذه الاختبارات.
- Playwright: Chromium على desktop وهاتف، جاهزية حقيقية وRTL/LTR وtheme persistence وإعادة الفحص وحالة تعطل API.
- UI مستقلة: `pnpm test:ui` تستخدم fixtures معلنة على مستوى network داخل الاختبار فقط لفحص العرض والتفاعل عند غياب الخدمات. مرور هذه الاختبارات لا يثبت توفر الخدمات ولا يعوض Integration/E2E.
- CI: تنسيق فحص ثابت باستخدام lockfile؛ تشغيل الخدمات والمهاجرات قبل التكامل والمتصفح؛ حفظ trace عند فشل المتصفح.

لا يكفي مرور Unit لقبول عزل المؤسسات. FORCE RLS والأذونات تتطلب حساب app فعلياً محدوداً. ملفات schema والسياسات نفسها لا تثبت صحة العزل دون الاختبارات.

المراحل اللاحقة تضيف اختبارات دورة العمل الموصوفة في master prompt وnegative authorization لكل endpoint. قياس الأداء يأتي مع workloads حقيقية؛ لا أرقام مختلقة.
